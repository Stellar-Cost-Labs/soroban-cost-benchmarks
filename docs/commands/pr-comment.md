# `pr-comment`

Post or update the cost summary comment on a GitHub pull request.

## Usage

```
soroban-cost-benchmarks pr-comment \
  --owner <owner> --repo <repo> --pr-number <n> \
  --forecast <path> [--wasm-metrics <path>] [--comparison <path>] [--dry-run]
```

| Option | Meaning |
|---|---|
| `--owner <owner>` | **Required.** GitHub owner (user or org). |
| `--repo <repo>` | **Required.** Repository name. |
| `--pr-number <n>` | **Required.** Pull request number. |
| `--forecast <path>` | **Required.** Rent forecast JSON. |
| `--wasm-metrics <path>` | Optional. Adds a `WASM Metrics` section. |
| `--comparison <path>` | Optional. Adds a comparison section. |
| `--dry-run` | Render and print; make no API call. No token needed. |

## ⚠️ It requires an explicit `--forecast` and never fetches config itself

Unlike every other network-touching command, `pr-comment` has **no live-fetch path**.
Omit `--forecast` and it errors:

```
At least --forecast is required for pr-comment
```

This is a genuine deviation from the "live by default" policy the rest of the tool
follows. The bot's numbers are exactly as current as the forecast file you hand it, so
generate one that is fresh:

```bash
# step 1 — produce a fresh forecast (this step does the live fetch)
soroban-cost-benchmarks rent-forecast \
  --entry persistent:1024 --entry persistent:2048 --entry temporary:512 \
  --json > forecast.json

# step 2 — post it
export GITHUB_TOKEN=ghp_...
soroban-cost-benchmarks pr-comment \
  --owner myorg --repo myrepo --pr-number 42 \
  --forecast forecast.json
```

## Token requirements

`GITHUB_TOKEN` is required unless `--dry-run` is set. The token needs **`Issues: write`**
on the target repository — PR comments are issue comments. That grant is per-repository
on the token's installation, not token-wide.

## Update-in-place

The comment begins with the hidden marker `<!-- soroban-cost-benchmarks bot -->`. On each
run the bot lists the PR's comments, finds the one carrying that marker, and updates it.
If none exists it creates one.

```bash
soroban-cost-benchmarks pr-comment ... --pr-number 42
# Comment posted/updated: ID 5652127269
```

The same ID is printed on every subsequent run — that is how you can tell it updated
rather than duplicated.

## Preview

```bash
soroban-cost-benchmarks pr-comment \
  --owner myorg --repo myrepo --pr-number 42 \
  --forecast forecast.json --dry-run
```

```
[dry run] no GitHub API call made — printing the comment body that would be sent to myorg/myrepo#42
```

The body goes to stdout, the banner to stderr, and no HTTP request is made. Use this in
CI to review output without granting write permissions.

## Comment layout

```
<!-- soroban-cost-benchmarks bot -->
## 📊 Soroban Cost Summary

**Network:** `testnet` | **Config ledger:** `4652629` | **Source:** `rpc:getLedgerEntries@4652629 (testnet)` | **Snapshot:** `...`

### Storage Rent Forecast
| Tier | Days | Size (B) | Rent (stroops) | Rent (XLM) | Daily (stroops) |

**Total by horizon:** ...

### WASM Metrics          ← only when --wasm-metrics is supplied
<comparison section>       ← only when --comparison is supplied
---
*Generated by soroban-cost-benchmarks — built on soroban-cost-estimator*
```

Sections with no input are omitted rather than rendered empty.
